# Відповідь на інструкцію Степан ↔ sender

Інструкцію прочитали. Ендпоінт відповідає вашому контракту. Нижче — що готово, що потрібно
від вас, і чотири питання без відповіді.

---

## Готово з нашого боку

| | Стан |
|---|---|
| `POST /api/v1/sender/inbound-callback` | працює, перевірено запитом з інтернету |
| Дедуплікація за `external_id` | є, повтор ігнорується |
| Швидкість відповіді | 0.26–0.49с виміряно на бойовому, ваш ліміт 5с |
| Перевірка `X-Sender-Signature` | написана, порівняння за сталий час — чекає лише секрет |
| `Authorization: Bearer` як альтернатива | приймаємо |
| IP-allowlist | приймаємо |
| `type_send = out` | не обробляємо як звернення ліда |

Зараз ендпоінт у **відкритому режимі** — шліть без заголовків, можна починати одразу.

Уточнення, щоб не було непорозуміння: сьогодні ендпоінт **лише приймає й записує**. Відповіді
лідові ще не йдуть — для них бракує MCP-доступу і мапінгу ваших id на нашу філію. Тобто
«обробка асинхронна» поки означає «нічого важкого в запиті не робиться», а не готовий
конвеєр відповідей.

---

## Пункт 4: наш формат телефону

Зберігаємо **E.164 з плюсом**: `+6281234567890`.

Ваш `from` (wa-id, міжнародний без плюса) ми нормалізуємо самі — перевірено:
`6281234567890` → `+6281234567890`. Доробок з вашого боку не треба.

Одне прохання: підтвердьте, що `from` **завжди міжнародний**. Локальний формат (`08…`) ми
теж розпізнаємо, але тільки як індонезійський — а серед лідів філії трапляються іноземні
номери, і для них здогад за замовчуванням був би хибним.

---

## Автентифікація

Оберіть, що зручніше:

1. **IP-allowlist** — дайте адреси, з яких ходить sender. Без змін у вашому коді, і відкритий
   режим вимикаємо того ж дня.
2. **HMAC-підпис** — як у вашій інструкції. Секрет передайте окремим захищеним каналом, не
   файлом і не в листуванні.

---

## Чотири питання без відповіді

**1. Ретраї.** У першому документі сказано: `UrlCallback` робить POST з `connect_timeout 5с`,
**помилки лише логуються**. Отже якщо наш сервіс саме перезапускається (а деплой його
перезапускає), повідомлення ліда зникає безслідно: у вас воно є, до нас не дійшло, дізнатися
нема як. Достатньо трьох спроб з відступом — або методу «віддай inbound з такого часу», щоб
ми звірялись.

**2. Що повертає відправка при помилці.** Треба відрізняти «не доставлено клієнту»
(ескалюємо на менеджера) від «сервер недоступний» (повторюємо). Помилка тут коштує або
мовчання лідові, або дубля.

**3. Тестовий контур.** Проєкт/філія або номер, на якому ганяємо інтеграцію, не чіпаючи
живих лідів.

**4. Ліміти.** Скільки повідомлень на хвилину безпечно для номера.

## Що чекаємо від вас

- Перелік `project_id` / `branch_id` — без нього мапінг на нашу філію не зробити.
- Секрет HMAC або список адрес.
- MCP-доступ (URL + токен). Якщо MCP затримується — почнемо з REST `conversation/send`,
  він нас влаштовує.
